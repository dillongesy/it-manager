# Hosting the Field App on the internet

The Field App is designed to be internet-facing: it holds no sensitive data, keeps its
own copy of the branding, and never contacts the Portal (the bridge is Portal → Field
only). This document covers the supported setup and the planned next stages.

## Stage 1: same host, published through Nginx Proxy Manager (supported)

The bundled `proxy` service (Nginx Proxy Manager) is the Field App's entrance. It listens
on the server's port 4443, and the router maps the public port 443 to it. The steps are
in [README.md, Publishing the Field App](../README.md#3-publishing-the-field-app).

What protects the Portal in this stage:
- internet traffic reaches only the proxy, through the router's port mapping;
- the proxy shares no Docker network with any Portal container;
- portal-web and portal-api refuse the proxy's network, and portal-web accepts the office
  network only;
- the firewall drops traffic from the proxy's network to the Portal and admits only the
  office network to the Portal (443) and the proxy admin (81);
- the one-way bridge.

The remaining shared element is the host itself.

## Stage 2 — Field on its own host (planned)

The goal is to remove the shared-host risk. The plan:

1. Add a `docker-compose.field.yml` profile that runs only `proxy`, `field-web`,
   `field-api`, `field-db` and `init`, with `init` able to generate only Field secrets.
2. Expose the bridge on the Field host as an mTLS endpoint. The Portal host gets a
   client certificate (generated by `init` on the Portal side, pinned on the Field side),
   in addition to the service token and a source-IP allow-list.
3. Add admin fields under **Admin → System → Field App**: Field URL, bridge client
   certificate download, and connection test, so the pairing is done in the UI instead of
   by editing files.
4. `install.sh --role field` / `--role portal` to install each half.
5. On the Field host, the firewall allows 80/443 from anywhere and the bridge port only
   from the Portal host's IP.

## Stage 3 — hardening for public exposure

- Rate limits per IP on Field login (already 20 per 15 minutes) plus progressive delays.
  Consider fail2ban on the proxy's access log.
- Two-factor authentication (available): set the Field App policy to Required in
  Admin → Security.
- Optionally put Cloudflare (proxied DNS) or similar in front. The proxy then needs
  the CDN ranges as trusted proxies so client IPs stay correct.
- Uptime and certificate-expiry monitoring.
- Scheduled `scripts/purge-imported.js` on the Field side, so imported captures don't
  linger on the internet-facing database.
