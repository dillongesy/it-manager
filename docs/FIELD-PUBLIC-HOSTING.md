# Plan: putting the Field App on the internet

Today the Field App runs on the same host as the Portal and is LAN-only by default. It
was designed to be internet-facing (it holds no sensitive data, and the bridge is
Portal → Field only), so exposing it later is a configuration change, not a rewrite.
This document is the plan, in the order to do it.

## Stage 1 — same host, public Field hostname (supported now)

1. Point a DNS name (for example `field.example.com`) at your public IP, and forward TCP
   80/443 from the router to this server.
2. Re-run `sudo ./install.sh`, choose **domain** mode, and answer **yes** to "Allow the
   Field App from the internet". This sets:
   - `FIELD_SITE=field.example.com`, `FIELD_TLS=tls you@example.com` (Let's Encrypt)
   - `FIELD_ALLOWED_RANGES=0.0.0.0/0`
   - DOCKER-USER: 80/443 open (needed for certificate issuance and the shared 443).
3. The Portal hostname stays LAN-only. Caddy aborts any non-LAN client for it
   (`PORTAL_ALLOWED_RANGES=private_ranges`), even though 443 is now open.

What protects the Portal in this stage: the network matrix (the Field side has no route to
it), Caddy's per-hostname LAN check, and the one-way bridge. The remaining shared element is
the host itself.

## Stage 2 — Field on its own host (planned)

The goal is to remove the shared-host risk. The plan:

1. Add a `docker-compose.field.yml` profile that runs only `edge`, `field-web`,
   `field-api`, `field-db` and `init`, with `init` able to generate only Field secrets.
2. Expose the bridge on the Field host as an mTLS endpoint. The Portal host gets a
   client certificate (generated by `init` on the Portal side, pinned on the Field side),
   in addition to the service token and a source-IP allow-list.
3. Add admin fields under **Admin → System → Field App**: Field URL, bridge client
   certificate download, and connection test, so the pairing is done in the UI instead of
   by editing files.
4. `install.sh --role field` / `--role portal` to install each half.
5. On the Field host, the firewall allows 80/443 from anywhere and the bridge port only
   from the Portal host's IP.

## Stage 3 — hardening for public exposure

- Rate limits per IP on Field login (already 20 per 15 minutes) plus progressive delays.
  Consider fail2ban on Caddy's access log.
- Optional TOTP for Field accounts.
- Optionally put Cloudflare (proxied DNS) or similar in front. Caddy then needs
  `trusted_proxies` set to the CDN ranges so client IPs stay correct.
- Uptime and certificate-expiry monitoring.
- Scheduled `scripts/purge-imported.js` on the Field side, so imported captures don't
  linger on the internet-facing database.
