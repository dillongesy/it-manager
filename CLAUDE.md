## Architecture in one screen

```
internet/LAN ─▶ edge (Caddy :80/:443/:FIELD_PORT=8443)   only container with published ports
                 ├─ portal_edge ─▶ portal-web ─ portal_app ─▶ portal-api ─ portal_db ─▶ portal-db
                 │                                             │  └─ portal_egress ─▶ internet (integrations)
                 │                                             └─ bridge ─▶ field-api (/api/service/* only)
                 └─ field_edge  ─▶ field-web  ─ field_app  ─▶ field-api  ─ field_db  ─▶ field-db
```

- **Networks.** Nine networks on `${NET_PREFIX:-172.29}.0–8.0/24`. All are
  `internal: true` except `public` and `portal_egress`.
- **One-way bridge.**
  - portal-api binds only `<prefix>.3.10` (`HOST` env), so field-api can't connect to it.
  - field-api: bridge-subnet callers get 404 on everything except `/api/service/*`
    (`SERVICE_ALLOWED_CIDR`, checked on the socket address), plus a service token.
  - Edge and field-web refuse `/api/service` outright.
- **Secrets.** `deploy/init/init-secrets.sh` writes per-service volumes
  (`secrets_portal_db/api`, `secrets_field_db/api`; mode 0400, mounted read-only, uid 70
  for Postgres, uid 1000 for Node). It also writes `reveal/setup_code` and
  `reveal/bundle.json`. Apps read secrets via `*_FILE` env vars
  (`src/config/load-secrets.js`).
- **Hardening.**
  - All containers: `cap_drop: ALL` and `no-new-privileges`.
  - App containers run read-only, as non-root.
  - Postgres and Caddy add back only the caps they need.
- **Images (6):** `init`, `edge`, `portal-api`, `portal-web`, `field-api`, `field-web`.
  Build locally with `docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build`.

## Gotchas learned

- Embedded Postgres on Windows defaults to WIN1252. Create test DBs with
  `ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0`.
- Running the Field API locally with `SERVICE_ALLOWED_CIDR=127.0.0.0/8` makes *every*
  local non-service request 404. That's correct behavior, not a bug.
- Portal unit tests need `test/setup-env.js` (already wired into `npm test`).
- `docker compose run portal-api …` would clash with the fixed IP. Use
  `docker compose exec` instead (as `import-existing.sh` does).
- Python heredocs that contain `"""` next to shell quotes broke twice in Git Bash. Use
  the Edit/Write tools for those edits.
- Browsers send no SNI for `https://<ip>`, so Caddy needs `default_sni` (from
  `DEFAULT_SNI` in .env) or LAN mode fails with ERR_SSL_PROTOCOL_ERROR. This was found
  on the first real run, 2026-11-08, on ITM-Sandbox (192.168.200.45, `ssh itm-sandbox`,
  user `dillon`).
- Migrations are tracked by version only (no checksums), so editing comments in old
  migration files is safe for existing databases.
- Test fixtures must not carry real data (staff, customers, tenant IDs, LAN addresses).
  Use Dana Grant (DG), Riley Morgan (RM), Northwind, Contoso, Lakeside, `192.168.50.x`.
