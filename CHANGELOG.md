# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- Nginx Proxy Manager follows its 2.x releases (`PROXY_TAG`) instead of `latest`.
- `scripts/backup.sh` is the backup engine behind Admin → Backups; backups are single
  files (`itm-<date>-<time>.tar.zst[.gpg]`) and include Nginx Proxy Manager's data.
- `sudo ./install.sh` on an installed server checks that the internal address range is
  still free before changing anything.
- The Admin tabs wrap onto a second line on narrow screens instead of scrolling.
- Re-running `sudo ./install.sh` on an installed server also pulls the current images.
- **Upgrading from 1.0.0:** reinstall (`git pull`, then `sudo ./install.sh` on a clean
  server, or import a backup with `scripts/import-existing.sh`). The ports, the firewall
  and the installation flow changed.
- Installation is set up in the browser: `install.sh` asks nothing, and the setup wizard
  at `https://<server>` collects the office network, optional Portal DNS names, the
  internal subnet prefix (checked live), the firewall choice, the certificate validation
  mode and the update schedule, then shows the installation's live log.
- Ports: the Portal is on 443 (office network only); Nginx Proxy Manager serves the Field
  App on 4443, with the router mapping the public port 443 to it; the proxy admin page is
  on 81 (office network only); port 80 is open to the internet only with HTTP certificate
  validation.
- The firewall governs only the app's published ports (Docker's DOCKER-USER chain, kept
  by a systemd unit) and no longer changes ufw or SSH.
- Updates are plain `docker compose pull && docker compose up -d`, scheduled by the host
  helper; `update.sh` is removed.
- The Caddy edge container is removed. The Portal serves its own HTTPS with a certificate
  from a local CA generated by `init`, and works by IP address without SNI.
- Printed work orders and customer exports use the primary brand color.
- A new work order's default rate is the customer's rate named like the first default
  rate, falling back to the customer's first rate.
- Source comments describe current behavior only.

### Added
- Scheduled backups (Admin → Backups): on by default every day at 01:00 and before each
  update; Proxmox-style retention (last, daily, weekly, monthly, yearly); storage in a
  folder, an SMB share or an NFS export, tested before saving; AES-256 encryption with a
  passphrase; optional encryption keys inside encrypted backups; verification; protected
  backups; restore from the Portal (password required) or with
  `sudo ./install.sh backup restore`. An update is skipped when the backup before it fails.
- Dashboard alerts for admins: failed, overdue or disabled backups, backups kept only on
  the server, a failed or skipped update, and a new major version of Nginx Proxy Manager.
- Admin → System shows Nginx Proxy Manager's installed version and latest release, and how
  to move to a new major version (`sudo ./install.sh proxy-version N`).
- Admin → Certificate explains when the certificate changes and how to remove an old one.
- The Field App on the office network without any proxy set up: `https://<server>:4433`,
  HTTPS with a certificate from the server's CA, office addresses only.
- Admin → System → Office network: change the networks allowed to use the Portal and the
  server's local DNS names after installation. The certificates are re-issued and the
  web containers restarted; a change that would lock out the admin making it is refused.
- Setup wizard (`installer` image) served before installation, with the host helper that
  performs the installation from a whitelisted request.
- Two-factor authentication (TOTP) for the Portal and the Field App, with an Off / Optional
  / Required policy per app, QR-code setup, ten single-use recovery codes, enrollment
  during sign-in when required, and admin reset.
- Admin → System: automatic update schedule, "Update now", the last update's log, the
  installation log, and the firewall status.
- Admin → Certificate and `/certificate`: how to trust the server's certificate on
  Windows (by hand, PowerShell, Group Policy, Intune), iPhone, Android and macOS.
- Admin → Billing: configurable default hourly rates for new customers.
- Admin → System → Storage: disk capacity, database and file sizes, growth rate and a
  forecast of when the disk fills up, plus an admin banner when space runs low.
- Bundled Nginx Proxy Manager for publishing the Field App, attached only to the Field
  App's network.
- The Portal refuses the reverse proxy's network in nginx, in the API and in the firewall.

### Fixed
- The arm64 web image build could hang under QEMU emulation; the frontend build stage
  now runs natively, and build jobs time out after 45 minutes.

## [1.0.0]

### Added
- Scheduled backups (Admin → Backups): on by default every day at 01:00 and before each
  update; Proxmox-style retention (last, daily, weekly, monthly, yearly); storage in a
  folder, an SMB share or an NFS export, tested before saving; AES-256 encryption with a
  passphrase; optional encryption keys inside encrypted backups; verification; protected
  backups; restore from the Portal (password required) or with
  `sudo ./install.sh backup restore`. An update is skipped when the backup before it fails.
- Dashboard alerts for admins: failed, overdue or disabled backups, backups kept only on
  the server, a failed or skipped update, and a new major version of Nginx Proxy Manager.
- Admin → System shows Nginx Proxy Manager's installed version and latest release, and how
  to move to a new major version (`sudo ./install.sh proxy-version N`).
- Admin → Certificate explains when the certificate changes and how to remove an old one.
- Docker Compose stack: edge (Caddy), Portal web/API/database, Field web/API/database,
  and a secret-generating `init` service, published to GHCR for amd64 and arm64.
- `install.sh` (Docker install, settings, internal subnet check, firewall, start) and
  `update.sh`.
- Setup wizard gated by a one-time setup code, and a one-time reveal of the recovery
  secrets.
- Admin area: users and roles, integrations (encrypted, applied without a restart),
  branding (pushed to the Field App), security, and system status.
- Lazy-loaded Portal pages and on-demand PDF rendering.
- Integration credential changes discard cached OAuth tokens and data immediately.
